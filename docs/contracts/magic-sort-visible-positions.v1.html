Vertrag v1: Magic Sort nach sichtbaren Positionen

Versprechen

Als Nutzer wird die Magic-Sort-Anordnung anhand der tatsächlich sichtbaren vertikalen Positionen berechnet. Verbundene Test Cases und Bugs landen dadurch möglichst auf derselben Höhe; eingeklappte Suiten und Filter werden exakt berücksichtigt.

Verbindliche Anforderungen

IDAnforderung
MSV-01Magic Sort berücksichtigt ausschließlich die in beiden Spalten aktuell sichtbaren, nicht herausgefilterten Test Cases und Bugs sowie ihre sichtbaren Beziehungen.
MSV-02Jede sichtbare Suite-Kopfzeile zählt auf der Test-Case-Seite als genau eine Höheneinheit. Bei eingeklappter Suite zählt nur ihre Kopfzeile; ihre verdeckten Test Cases erhalten keine Position und beeinflussen die Optimierung nicht.
MSV-03Jeder sichtbare Test Case und jeder sichtbare Bug zählt als genau eine zusätzliche Höheneinheit. Die Positionsdifferenz einer sichtbaren Beziehung ist der Betrag aus Test-Case-Position minus Bug-Position.
MSV-04Magic Sort minimiert die Summe aller Positionsdifferenzen und zusätzlich die Anzahl der Linienkreuzungen. Ein angenommener Animationsschritt darf keinen dieser beiden Werte verschlechtern und muss mindestens einen strikt verbessern.
MSV-05Ist eine sichtbare Anordnung hinsichtlich beider Werte gleichwertig, bleibt die bestehende Reihenfolge unverändert. Insbesondere wird ein bereits höhengleich verbundener Bug nicht ohne Verbesserung verschoben.
MSV-06Test Cases dürfen weiterhin ausschließlich innerhalb ihrer eigenen Suite umsortiert werden. Der Ein-/Ausklappzustand, Filter und Beziehungen selbst bleiben unverändert.
MSV-07Die bestehende bewusste Auslösung, Animation, Zugänglichkeit und Persistenz von Magic Sort bleiben erhalten.

Nicht Teil dieses Vertrags

  • Automatisches Sortieren beim Laden oder beim Ein-/Ausklappen.
  • Änderungen an Azure DevOps, Beziehungen oder Suite-Zugehörigkeiten.
  • Eine Rückgängig-Funktion.
